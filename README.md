# קורא חיישן קרקע 7-in-1 (Android)

אפליקציית אנדרואיד (Kotlin) שמתחברת לחיישן קרקע 8-פרמטרים (טמפרטורה,
לחות, EC, מליחות, NPK, pH) דרך USB ומציגה את הנתונים בזמן אמת.

## איך זה עובד

החיישן מוציא USB עם ממיר USB-to-Serial פנימי (CH340). האפליקציה:

1. מזהה את החיישן דרך הספרייה [usb-serial-for-android](https://github.com/mik3y/usb-serial-for-android).
2. פותחת חיבור serial ב-9600 baud, 8N1.
3. שולחת כל 2 שניות בקשת **Modbus RTU** (function code 0x03) לכתובת
   slave 1, לקרוא 8 רגיסטרים החל מכתובת 0x0000.
4. מפענחת את התגובה לפי מפת הרגיסטרים הבאה - **מאומתת בפועל מול
   אפליקציית היצרן** (לא רק ניחוש):

   | רגיסטר | פרמטר         | יחידה גולמית -> תצוגה |
   |--------|---------------|------------------------|
   | 0      | טמפרטורה      | raw/10 = °C (signed)   |
   | 1      | לחות          | raw/10 = %RH           |
   | 2      | EC            | raw = µS/cm            |
   | 3      | מליחות        | raw = mg/L             |
   | 4      | חנקן (N)      | raw = mg/kg            |
   | 5      | זרחן (P)      | raw = mg/kg            |
   | 6      | אשלגן (K)     | raw = mg/kg            |
   | 7      | pH            | raw/100 = pH           |

   (הניחוש הראשוני היה עם 7 רגיסטרים בלבד וסדר טמפ׳/לחות הפוך - זה
   תוקן אחרי השוואה ישירה לתוצאות של אפליקציית היצרן.)

## פתיחת הפרויקט

אין צורך ב-Android Studio: ה-repo מכיל GitHub Action
(`.github/workflows/main.yml`) שבונה APK debug אוטומטית בכל push,
זמין להורדה תחת הטאב **Actions** → ה-run האחרון → **Artifacts**.

**חשוב לגבי התקנות חוזרות:** `app/debug.keystore` מוגדר כמפתח החתימה
הקבוע של כל build (ב-`app/build.gradle.kts`, `signingConfigs.debug`).
בלי זה, כל build ב-GitHub Actions היה נחתם במפתח אקראי חדש, ואנדרואיד
מסרב "לעדכן" אפליקציה קיימת עם מפתח שונה (בדרך כלל נכשל בשקט ומשאיר
את הגרסה הישנה על הטלפון). זה מפתח דמה (debug) בלבד, לא באמת סודי -
מותר וצריך לשמור אותו ב-git.

אם כן יש לך Android Studio: פתח את התיקייה, תן ל-Gradle Sync לרוץ,
חבר טלפון והרץ.

## מבנה הפרויקט

- `ModbusRtu.kt` - בניית בקשות Modbus RTU, חישוב CRC16, פענוח תגובות.
- `SoilSensorReading.kt` - מודל הנתונים + המרת רגיסטרים גולמיים לערכים.
- `UsbSerialHelper.kt` - ניהול חיבור USB, הרשאות, ולולאת polling.
- `MainActivity.kt` - מסך ראשי (רשת כרטיסיות) שמציג את הנתונים.

## עדכונים אחרונים

- **צבעי הכרטיסיות** נדגמו ישירות מפיקסלים בצילום מסך של אפליקציית
  היצרן (לא ניחוש) - ראה `colors.xml`. לפרמטר Salinity (שלא קיים
  באפליקציית היצרן שצולמה) נבחר צבע ניטרלי נפרד שלא מתנגש עם השאר.
- **מספר הגרסה** בראש המסך נקרא אוטומטית מ-`BuildConfig.VERSION_NAME`/
  `VERSION_CODE` - כלומר תמיד משקף את הבילד בפועל, אין צורך לעדכן טקסט
  ידנית בקובץ ה-XML יותר.
- **מיתוג AG-Sense**: נוסף כותרת "AG-Sense" וטקסט "Powered by AG-Sense".
  **לא הצלחתי להביא את הלוגו הרשמי מ-ag-sense.info** - יש הגבלת רשת
  בסביבת הפיתוח שמונעת גישה לאתר, ומקור חלופי שמצאתי (CB Insights) לא
  בטוח שמדויק/עדכני. אם תרצה את הלוגו האמיתי במסך, תעלה את קובץ ה-PNG/
  SVG ואוסיף אותו ל-`res/drawable` ואחליף את הטקסט ב-`ImageView`.

## עדכון: לוגו אמיתי

התקבל קובץ הלוגו האמיתי מהמשתמש (`ag_sense_logo.png`, ב-
`res/drawable-nodpi/`) - הוא כבר כולל את הטקסט "Powered by ag-sense"
והסלוגן, ולכן הטקסטים הנפרדים שהיו קודם הוסרו והוחלפו ב-ImageView יחיד.

## עדכון חשוב: ניקוי מבנה הריפו + תכונות חדשות

**נמצאה בעיה מהותית**: כתוצאה מגרירת התיקייה החוצה (ולא רק תוכנה) בכמה
העלאות עוקבות, נוצרו בריפו כמה עותקים מקוננים כפולים של הפרויקט
(`SoilSensorReader/SoilSensorReader/...` וכו'). ה-workflow (עם ה-`find`
שמאתר את `settings.gradle.kts`) תמיד תפס את העותק הראשון/הישן שהתגלה,
ולכן כמה builds ברצף בנו בפועל קוד ישן בלי שהמשתמש שם לב. **מקור זה
מתוקן** - כל התוכן הועבר לשורש הריפו בלבד, בלי קינון.

תכונות שנוספו באותו עדכון:
- כותרות הכרטיסים (אייקון + שם) גדלו ל-24sp, תואם לגודל הערכים המספריים.
- מזהה החיישן (USB Vendor/Product ID, Android Device ID, ומספר סידורי
  אם השבב מספק) מוצג מתחת לסטטוס החיבור.

## תפריט (⋮)

נוסף כפתור תפריט בפינת המסך העליונה, עם שתי אפשרויות:

1. **שם החיישן** - נותן שם לחיישן המחובר כרגע. השם נשמר לפי מזהה החיישן
   (VID:PID + מספר סידורי אם קיים) ב-SharedPreferences, כך שבכל פעם
   שאותו חיישן פיזי מתחבר (גם בעתיד, גם בטלפון אחר עם אותה התקנה), השם
   שניתן לו יוצג אוטומטית. אפשר לחבר כמה חיישנים שונים ולתת לכל אחד שם
   נפרד - ההבחנה ביניהם מבוססת על ה-VID:PID+מספר סידורי.
   **הגבלה**: חלק משבבי CH340 (הזולים) לא מספקים מספר סידורי אמיתי -
   במקרה כזה, שני חיישנים פיזיים זהים (ללא מספר סידורי) ישתפו את אותו
   מזהה ואת אותו שם שמור.
2. **גרסה ותאריך עדכון** - מציג את מספר הגרסה (`versionName`/
   `versionCode`) ואת תאריך/שעת הבנייה בפועל (`BuildConfig.BUILD_DATE`,
   מחושב אוטומטית בזמן ה-build ב-GitHub Actions, לא צריך לעדכן ידנית).
